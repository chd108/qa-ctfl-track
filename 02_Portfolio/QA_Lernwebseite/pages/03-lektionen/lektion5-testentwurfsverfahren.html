F 04 Rückblick: Zustandsbasierter Test

Was haben wir in der letzten Sitzung gelernt?

Ein Zustandsübergangsdiagramm modelliert das Verhalten eines Systems durch:

  • Zustand → Ereignis → Übergang → Aktion

Heute vertiefen wir das Thema mit zwei Arten der Überdeckung:

  • Anweisungsüberdeckung: Wurden alle Zustände mindestens einmal durchlaufen?
  • Zweigüberdeckung: Wurden alle Übergänge (Zweige) mindestens einmal getestet?
F 05 Überdeckung im Zustandsmodell
Abschnittsfolie · kein weiterer Inhalt
F 06 Anweisungsüberdeckung: Theorie + Beispiel

Definition

Stelle sicher, dass alle Zustände (Anweisungen) im Zustandsübergangsdiagramm mindestens einmal durchlaufen werden.

Testszenario: Login-System

Zustände: Start | Benutzername eingeben | Passwort eingeben | Eingeloggt | Fehler

Code des Login-Systems

startLogin()
...
disableContinueButton()
var username = getUsername()
requestPassword(username)
...
if(password == "neverUsePlaintextPwds")
{ loginUser()
  showProfileButton()
}
else {
    showError()
}
...
navigateHome()
logoutUser()
...

Testfälle für 100 % Anweisungsüberdeckung

  1. Start → Benutzername eingeben
  2. Benutzername eingeben → Passwort eingeben
  3. Passwort eingeben → Eingeloggt
  4. Passwort eingeben → Fehler
  5. Fehler → Passwort eingeben
  6. Eingeloggt → Start

Ablaufpfade

  • Pfad 1 (Erfolg): Start → Benutzername eingeben → Passwort eingeben → Eingeloggt → Start
  • Pfad 2 (Fehler): Start → Benutzername eingeben → Passwort eingeben → Fehler → Passwort eingeben
F 07 Zweigüberdeckung: Theorie + Beispiel

Definition

Stelle sicher, dass alle Übergänge (Zweige) zwischen den Zuständen mindestens einmal getestet werden. Zweigüberdeckung ist strenger als Anweisungsüberdeckung.

Testfälle für 100 % Zweigüberdeckung (Login-System)

  1. Start → Benutzername eingeben
  2. Benutzername eingeben → Passwort eingeben
  3. Passwort eingeben → Eingeloggt
  4. Passwort eingeben → Fehler
  5. Fehler → Passwort eingeben
  6. Eingeloggt → Start
  7. Passwort eingeben → Fehler → Eingeloggt → Start

Testfall 7 stellt sicher, dass auch der Übergang nach einem Fehler zurück zum erfolgreichen Login abgedeckt ist — dieser Pfad wird bei der reinen Anweisungsüberdeckung möglicherweise übersehen.

F 08 Vollständiges Beispiel: Login-System

Zustände (5)

  • Start
  • Benutzername eingeben
  • Passwort eingeben
  • Eingeloggt
  • Fehler

Übergänge (6)

  1. Start → Benutzername eingeben: Benutzer startet Eingabe
  2. Benutzername eingeben → Passwort: Benutzername übermittelt
  3. Passwort → Eingeloggt: Korrektes Passwort eingegeben
  4. Passwort → Fehler: Falsches Passwort eingegeben
  5. Fehler → Passwort: Erneut versuchen
  6. Eingeloggt → Start: Abmelden (Annahme)

F 09 Unterschied: Anweisungs- vs. Zweigüberdeckung

Was ist der Unterschied?

Codebeispiel

if (condition) {
    if (condition2) {
        System.out.println("Hey!");
    }
}

Analyse

  • true, true → "Hey!" wird ausgeführt → 100 % Anweisungsüberdeckung
  • true, false → keine Anweisung im inneren Block wird ausgeführt

Mit nur dem Testfall (true, true) wurden alle Anweisungen ausgeführt — aber der Zweig (true, false) wurde nie getestet!

Merksätze

  • Anweisungsüberdeckung garantiert keine Zweigüberdeckung!
  • 100 % Zweigüberdeckung garantiert 100 % Anweisungsüberdeckung!

Zweigüberdeckung ist die stärkere der beiden Methoden.

F 11 Erfahrungsbasiertes Testen: Exploratives Testen

Was ist es?

Ziel: Mehr über das Produkt lernen und ungetestete Bereiche entdecken.

Exploratives Testen kann in zeitlich begrenzten Sessions (Timeboxes) durchgeführt werden.

Wann einsetzen?

  • Wenn nur wenige oder unzureichende Spezifikationen vorliegen
  • Bei erheblichem Zeitdruck
  • Zur Ergänzung strukturierter Testverfahren

Unterschied zu strukturierten Tests

Beim explorativen Testen werden Testplanung und Testdurchführung gleichzeitig durchgeführt — der Tester lernt das System während des Testens kennen und passt seine Tests laufend an.

F 12 Erfahrungsbasiertes Testen: Intuitive Testfallermittlung

Was ist es?

Der Tester nutzt Erfahrung und Intuition, um Fehlerzustände vorherzusagen und gezielt zu testen.

Wann einsetzen?

  1. Nach strukturiertem Testen — um weitere übersehene Befunde aufzudecken
  2. Während des explorativen Testens
  3. Bei begrenztem Zeitrahmen

Unterschied zum explorativen Testen

  • Exploratives Testen: offen, lernend, ohne vordefinierten Plan
  • Intuitive Testfallermittlung: gezielt, basierend auf bekannten Fehlermustern und Erfahrungswissen

Beide ergänzen sich und gehören zur Kategorie des erfahrungsbasierten Testens.

Szenario: Geldautomat (ATM). Der Benutzer sieht zunächst den Startbildschirm, danach den „Warten auf PIN“-Bildschirm. Er hat drei Versuche. Bei korrekter PIN erhält er Zugang zum Konto. Bei zu vielen Fehlversuchen wird die Karte einbehalten.

Aufgaben:

  1. Bestimme die Zustände, Übergänge und Ereignisse
  2. Erstelle die Zustandsübergangstabelle
  3. Erstelle das Zustandsübergangsdiagramm

Szenario: Ein Entwickler fragt dich, ob seine Unit-Tests seinen gesamten Code abdecken. Zur Vereinfachung wurde ein Teil des Codes durch println("Anweisung x") ersetzt.
